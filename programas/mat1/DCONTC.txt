%%HP: T(3)A(R)F(.);
\<<
  @ DCONTC - nucleo de DCONT. Continuidad en el punto de corte.
  @ Uso:  'FI(X)' 'FD(X)' A DCONTC
  @ Deja: n1 = { LI LD IG ES }
  @         LI = limite por izquierda, LD = limite por derecha,
  @         IG = 1 si los dos limites coinciden,
  @         ES = mayor que 0 si alguno es infinito (discont. esencial).
  @
  @ Sin INFORM ni MSGBOX A PROPOSITO: eso lo pone DCONT. Separado asi,
  @ el harness puede correr este objeto con argumentos de pila y
  @ comparar el resultado, que con el formulario soldado no se podia.
  @
  @ Limites LATERALES de verdad: la rama izquierda en 'X=a-0' y la
  @ derecha en 'X=a+0'. Antes era el limite ordinario, y con una rama que
  @ revienta en el corte el CAS abria "Unsigned inf. Solve?" y devolvia el
  @ infinito SIN signo: '1/X' por izquierda en 0 daba +oo en vez de -oo.
  @ Medido (harness/casos-lateral.txt): los laterales dan el signo bien.
  @ Se arman como texto y se compilan con STR\->, porque desde la pila
  @ 'X' A 0 - = se reduce a X=a. Igual que DCONTFC.
  @
  @ NO requiere el global INF: el punto de corte es finito, y el
  @ infinito se detecta por su caracter (ver abajo), no comparando.
  \-> FI0 FD0 A
  \<<
    @ Guardian de profundidad (AGENTS.md 2.11): IFERR no limpia la pila,
    @ asi que los argumentos de un comando que fallo quedan apilados.
    @ Se anota la profundidad al entrar y se tira lo que sobre al salir.
    DEPTH \-> D0
    \<<
      FI0 IF DUP TYPE 2 == THEN STR\-> END \-> FI
      \<<
        FD0 IF DUP TYPE 2 == THEN STR\-> END \-> FD
        \<<
          @ a como texto sin tildes, para armar 'X=a-0' y 'X=a+0'
          A \->STR
          IF DUP 1 1 SUB "'" == THEN DUP SIZE 1 - 2 SWAP SUB END
          \-> AS
          \<<
          "'X=" AS + "-0'" + STR\-> "'X=" AS + "+0'" + STR\->
          0 0 0 0 \-> EQI EQD LI LD IG ES
          \<<
            IFERR FI EQI LIMIT EVAL THEN "INDEF" END 'LI' STO
            IFERR FD EQD LIMIT EVAL THEN "INDEF" END 'LD' STO
            IFERR LI \->NUM LD \->NUM - ABS .0000001 < THEN LI LD SAME END 'IG' STO
            @ Deteccion del infinito POR EL CARACTER, no por SAME contra INF.
            @ Probado en la maquina: con rama izq '1/X' y corte 0, LIMIT
            @ devuelve +oo (con el signo pegado, que es como la calculadora
            @ lo escribe sola) y el INF guardado por DINF es el oo pelado,
            @ asi que SAME daba falso y el veredicto salia "SALTO FINITO".
            @ El caracter oo tiene codigo 159 y aparece igual en +oo, -oo
            @ o 2*oo, asi que POS lo encuentra en todos.
            LI \->STR 159 CHR POS LD \->STR 159 CHR POS + 'ES' STO
            @ Red de seguridad: si el CAS devolvio un numero gigante en vez
            @ del simbolo, tambien es asintota vertical.
            @ Solo actua si la deteccion por caracter NO encontro nada. Antes
            @ pisaba ES siempre, y con eso tapaba si el detector primario habia
            @ funcionado: el harness veia ES=1 (de esta red) tanto cuando el
            @ caracter estaba como cuando no. Ahora el VALOR de ES dice quien lo
            @ detecto: 3 = por el caracter oo, 1 = por el tamano del numero.
            IF ES 0 ==
            THEN
              IFERR
                LI \->NUM ABS LD \->NUM ABS MAX 1000000000 >
                IF THEN 1 'ES' STO END
              THEN
              END
            END
            LI LD IG ES 4 \->LIST
            \-> R \<< DEPTH D0 - DROPN R \>>
          \>>
          \>>
        \>>
      \>>
    \>>
  \>>
\>>
